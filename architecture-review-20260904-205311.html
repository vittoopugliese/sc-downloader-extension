Problem

`processTrack` y `downloadSingleTrack` repiten resolución, construcción, guardado, revocación y lifecycle de keepalive dentro de un `BulkJobManager` que además posee el estado del job.

Solution

Extraer un deep module interno para la ejecución de una pista. El loop bulk y el comando single delegan la secuencia completa; el estado del job queda fuera.

Benefits

  • locality: cleanup y retries viven una vez
  • leverage: dos flujos comparten una implementation
  • tests cruzan un solo interface
  • deletion test: la secuencia reaparece en dos callers

Problem

La elección entre `chrome.downloads` y File System Access aparece en los dos paths de ejecución. `directory-storage.js` conoce nombres y handles, pero el caller conoce el transporte y el momento de revocar.

Solution

Concentrar selección, naming, persistencia y errores del destino en un deep module. Mantener cada mecanismo concreto como adapter detrás del seam.

Benefits

  • locality: permisos y nombres cambian juntos
  • leverage: single y bulk comparten la decisión
  • tests sustituyen cada adapter
  • two adapters make the seam real

Problem

`content.js` mezcla clasificación, HTML hydration, client id, tres formas de paginación, freshness por URL, retries, estado SPA y mensajería. Los extractores de likes, playlist y user tracks repiten fetch, validación y publicación.

Solution

Dar profundidad a un page intake module que posea identidad, hydration, paginación y freshness. El observer sólo coordina el cambio de página; popup e inline consumen el mismo resultado.

Benefits

  • locality: bugs de stale data se concentran
  • leverage: un normalizador cubre tres kinds
  • tests ejercitan datos sin DOM completo
  • deletion test: el guard de freshness no reaparece en cada extractor

Problem

`SCStreamSelector` concentra parte de la policy, pero background todavía expone operaciones separadas para stream, original y refresh. El commit de 404 tocó cuatro archivos porque la decisión de retry cruza el seam.

Solution

Hacer que un solo deep module posea selección de formato, preferencia por original, fallback y refresh. Dejar public y OAuth como adapters de transporte concretos.

Benefits

  • locality: 401/403/404 se decide una vez
  • leverage: callers no conocen la policy
  • tests sustituyen transportes con mock adapters
  • menos mensajes con significado duplicado

Top recommendation

Unificar la ejecución de una pista

Es el seam con mayor leverage inmediato: el mismo trabajo ya existe en el path single y en el loop bulk, y concentra construcción, destino y cleanup. Profundizarlo reduce duplicación justo donde el historial muestra más cambios y hace que los tests crucen una sola interface.
