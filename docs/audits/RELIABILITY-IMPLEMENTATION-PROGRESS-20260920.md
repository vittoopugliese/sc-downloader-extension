# Reliability implementation progress

Checked against `docs/audits/RELIABILITY-MITIGATION-PLAN-20260920.md` on the current checkout. This is an interim report, not a release approval.

## Implemented in this working tree

- M1: bulk tracks have stable operation IDs. Offscreen joins duplicate builds and directory saves with the same ID and rejects a changed payload. A lost directory save response is not retried automatically. Bulk records `saving` before the save, checkpoints Chrome `downloadId` as soon as it is returned, and checks `downloads.search` after worker recovery. A save whose outcome cannot be proved becomes `ambiguous_save`, remains visible, and is excluded from automatic and failed-track retries. Confirmed saves retain their result if blob cleanup fails. Jobs with some failures end as `completed_with_errors`.
- M2: audio, playlist and cover responses are read by a bounded stream reader. It checks headers and counts chunks before concatenation. HLS workers share a 128 MiB segment budget. Covers are limited to 5 MiB. WAV size and a combined compressed/decoded/rendered/WAV estimate are checked before the final WAV allocation. `memory_budget_exceeded` stays typed through transformed export.
- M3: page hydration, SoundCloud bundles and player-track fallback keep their timeout active through body consumption. Non-success page responses are classified from their headers without waiting for a stalled body. The shared SoundCloud JSON adapter applies a 15-second request/body timeout, a 2 MiB streaming limit, invalid-JSON classification and typed `429`/`5xx` errors. Missing `oauth_token` is typed as `auth_required` at the cookie boundary; unknown or network failures are no longer rewritten as logout by page intake. Page extraction now has a generation-scoped `AbortController`: SPA navigation and SoundCloud authentication-cookie changes abort active fetch/body/retry waits, clear page caches and prevent old `/me` responses from publishing. Short user-track retries use an injected clock and one 10-second total wait budget; a retry that would exhaust the budget fails closed as `rate_limited`.

## Continuation on the 2026.10.5 checkout

- M1 recovery now keeps a known Chrome `downloadId` in `saving` while Chrome reports `in_progress`. It subscribes to `downloads.onChanged` before searching, then marks the track `done` or `failed` when Chrome reports `complete` or `interrupted`. A missing result, search error, or five-minute wait becomes `ambiguous_save`; it never starts another file for that track automatically.
- Reproduced the prior failure with a state-machine test: recovery immediately changed an active download from `saving` to `ambiguous_save`. The same test now passes, including completion and interruption events with zero repeated track executions. `npm test` passed 41 verifications and `git diff --check` passed. `npm run test:e2e:download` passed outside the macOS sandbox with browser fixtures for offscreen, Chrome Downloads, selected folder and fallback. The recovery event itself remains source-level fixture evidence; browser worker suspension timing and the exact ZIP are not yet demonstrated.
- M1 folder fallback now distinguishes failures before file creation from uncertain outcomes after creation begins. The directory writer marks any create/write/close failure `ambiguous_save`; offscreen and the destination adapter preserve that code, and the adapter never starts a Chrome Downloads fallback for it. Tests reproduced both failures before the fix: the writer returned an untyped error, and the adapter started a second save for an uncertain write. All 41 local verifications and the Chromium download E2E pass after the fix. This is a conservative rule: some failed create attempts may leave no file, but they require the user to inspect the folder before retrying.
- M3 page/API timeout coverage reproduced two failures before the fix: an HTML body could remain pending after headers forever, and a `503` with a stalled body became `network_timeout` instead of `service_unavailable`. Shared JSON tests also cover a stalled body, an oversized declared body, streamed JSON, invalid JSON and `Retry-After`. All 41 local verifications pass. Chromium download, popup and Likes E2E pass on this tree; these remain fixture/source-tree evidence, not live SoundCloud or extracted-ZIP evidence.
- M3 continuation now bounds authenticated Likes pages to 2 MiB and 15 seconds through body completion, carries `Retry-After` into `retryAt`, and keeps auth/rate-limit/network/timeout/service/invalid-response causes distinct. User-track pagination no longer shortens a long provider `Retry-After` into an early retry. Artwork checks declared and streamed bytes, cancels failed readers and times out through body consumption. Commerce POSTs remain non-retried, have a 15-second response-body timeout and 256 KiB response limit, and a timeout no longer blocks the serialized queue. `/me` maps only missing/rejected authentication to `auth_required`; negative profile tests preserve the other typed causes. The 41 local verifications, Player Tools unit/service tests and Likes browser E2E pass after these changes.
- M3 navigation and retry closure reproduces and covers four stale-work cases: navigation aborts a pending page request, authentication invalidation prevents an old profile from publishing, abort during `Retry-After` clears the timer without another request, and repeated short delays stop at the injected-clock budget. Cookie changes are broadcast by the worker to every matching SoundCloud content script; tabs without a receiver do not fail the broadcast. All 41 local verifications plus popup and download Chromium E2E pass on this tree.
- M4 foundation adds a dedicated free-bulk IndexedDB, separate from Likes Explorer/licensing. Jobs keep compact enumeration counters and account/source/epoch context; tracks, seen IDs and cursor checkpoints live in separate stores. A page transaction deduplicates tracks and commits its next cursor atomically, replaying an already committed page without inserting twice. Cursor cycles become `partial`, requested limits stop at the exact eligible count, cancellation invalidates late pages by epoch, and `429`/network pauses retain `retryAt` and the current cursor. The runtime script is included in the worker and production package, but the existing content→popup→`START_BULK_JOB` path has not yet been switched to it.

## Evidence

- Local: `npm test` passed 41 verifications. Added tests for concurrent duplicate offscreen builds/saves, interrupted bulk recovery, Chrome ID reconciliation, unbounded chunked bodies, and synthetic large WAV output.
- Browser fixtures: `npm run test:e2e:download` and `npm run test:e2e:popup` passed outside the macOS sandbox on the current M3 tree. The download test covered offscreen, Chrome Downloads, selected folder and fallback. Likes E2E also passed after the preceding Likes HTTP/artwork changes. `npm run test:e2e:bulk-store` passed with real IndexedDB, a reload between pages, duplicate/replay/cycle/cancel cases, an exact 50-track limit and 50,000 compact track records across 250 page commits (3.1 seconds measured inside Chromium). These tests did not use a live SoundCloud session or the exact final ZIP.

## Still required by the mitigation plan

- M1: durable operation records for singles/loops; full reconciliation of in-progress Chrome downloads and folder writes; bounded durable deduplication history.
- M2: page HTML/bundle reads still need byte limits; measured process memory under repeated jobs and ChromeOS, and comprehensive HLS aggregate tests remain open.
- M4: connect worker-side enumeration and the download runner to the new store; reduce `storage.session` to the UI summary/active ID; paginate selection messages; migrate active legacy jobs; and add real popup All click-through/restart tests. M5–M8 remain open: Explorer integrity and cost work, offscreen leases/cancellation, HLS/security coverage, and exact ZIP smoke tests.
- Commercial release gate: Cloudflare/Lemon Squeezy deployment and reconciled sandbox/live purchase, production entitlement and refund tests, and a final ZIP without test login remain open. No external production action was taken.

Do not use this tree as a release candidate until the remaining gates are completed and measured.
